# ECK Digital Life Kernel v0.2.0 開發規格

**狀態：** Development Baseline（開發基線，尚未完成驗收）
**建立日期：** 2026-08-02
**前置版本：** v0.1.0 已通過並封存
**核心主題：** Contract-Guided Autonomous Learning（契約導向自主學習）

## 1. 文件決策

ECK v0.1.0 已證明核心可以持續運行、保存身分與事件、用外部證據驗證結果、
沉澱經驗與技能，並以受控能力執行研究、文件、圖像與隔離技能工作程序。
v0.2.0 不再以「加入更多固定功能」作為主要目標，而是建立一個可重複、可評量、
可回復的能力成長閉環，使模型能在固定安全邊界內提出候選方法、找出能力缺口、
製作或改善技能、接受驗證、比較前後表現，再決定是否保留成果。

本文件定義 v0.2.0 的開發範圍。建立文件或開始開發不代表 v0.2.0 已發布；只有
全部 release gate 通過後，套件與執行中核心才可正式宣稱為 v0.2.0。

## 2. 目前真實狀態

| 項目 | v0.1.0 已驗證 | v0.2.0 目標 |
| --- | --- | --- |
| 生命週期 | 可持續、暫停、睡眠、復原 | 工作程序可獨立重啟與熱切換 |
| 學習 | 經驗、知識、反思、技能帳本 | 可量化的能力增益閉環 |
| 思考模型 | 本機 Ollama，可替換 | 契約導向候選方案與修復迴圈 |
| 模型權重 | 未由 ECK 訓練 | 候選 LoRA 實驗室；禁止自動升級正式權重 |
| 網路研究 | Crossref 等受控公開來源 | 多來源證據圖、來源品質與資訊增益停止條件 |
| 技能建立 | Docker 隔離、測試後熱啟用 | 缺口驅動的產生、比較、回歸、回復 |
| 任務 | 對話、任務、課題與監督者 | 自主工作組合、優先度與長期進度控制 |
| 智慧證明 | 無 AGI 或超人類證明 | 固定基準與真實任務的版本化能力曲線 |

## 3. 長期使命與 v0.2 邊界

長期使命是建立一個服務人類、能持續取得證據、累積可轉移經驗、發現未知問題並
改善自身能力的本地數位生命核心。使命是方向，不是現況聲明。

v0.2.0 明確不宣稱：

- 已達成 AGI、意識、自主生命或超越全人類知識；
- 能在沒有官方介面與可追溯證據時自行操作任何社群或商城；
- 能任意修改主機系統、繞過平台規則、規避安全機制或花費真實金額；
- 對話變好等同模型權重已學習；
- 單一 LLM 自評可證明能力提升。

## 4. v0.2 成功定義

v0.2.0 成功不是事件數增加，也不是 GPU 長時間滿載，而是同一固定任務集在相同
資源條件下出現可重現的能力增益。每個增益都必須能回答：

1. 原本哪裡失敗？
2. 使用了哪個來源、經驗、技能或模型候選？
3. 修改了什麼？
4. 哪個固定驗證器判定成功？
5. 在未參與開發的保留集是否仍成功？
6. 若回歸，能否回到上一個可用版本？

## 5. 目標架構

```text
Human Mission / Curiosity / Supervisor / Failure Signal
                         |
                    Work Selector
                         |
             Contract-Guided Planner Brain
                         |
       Candidate Plan -> Action -> Evidence -> Verifier
             |                           |
             +-------- Repair Loop <-----+
                         |
        Experience Graph / Counterexample Memory
                         |
         Skill Forge / Prompt Candidate / LoRA Lab
                         |
       Sandbox Test -> Holdout -> Safety Regression
                         |
              Hot Activate or Roll Back
                         |
             Versioned Evaluation Curve
```

所有可改變外部狀態的動作仍需經過 Policy Gate。所有正向學習仍需 Success Contract、
外部證據與重現。工作選擇器可以自主排程，但不能改寫驗收標準來讓自己通過。

## 6. Autonomous Work Portfolio

核心不再只從固定題庫輪詢。Work Selector 每輪從以下來源建立候選工作：

- 人類下達的普通或緊急任務；
- 已登錄課題的準備工作，但預設只占 10%；
- 最近失敗或反例暴露的能力缺口；
- Experience Graph 中低覆蓋、高不確定或高價值的主題；
- 監督者針對近期學習提出的不重複考驗；
- 固定基準中退步或長期未改善的項目；
- 已驗證技能的變體、組合與遷移測試。

預設資源比例維持 90% 自主學習、10% 課題準備與執行。緊急人類任務可暫時覆寫，
完成後自動恢復。排程器必須避免用 Heartbeat、重複題目或無驗證摘要製造假進度。

每個工作具有主題、預期資訊增益、能力缺口、成本上限、停止條件、冷卻時間、
最近嘗試與相似度指紋。無新增證據、無新反例、無技能改善的重複工作會被降權。

## 7. Contract-Guided Brain

Brain 在 v0.2.0 的主要職責是提出候選方案，而不是決定自己是否成功。

### 7.1 候選迴圈

1. Kernel 固定任務目標、禁止條件、證據需求與資源上限。
2. Brain 產生一至三個結構化候選計畫。
3. Planner 進行 schema、能力、成本、風險與前置條件檢查。
4. 合格計畫進入執行；結果由外部工具與環境形成 Evidence。
5. Verifier 回傳通過、失敗、不可驗證或合約違反。
6. Repair Loop 只能根據可公開的錯誤摘要調整，最多重試固定次數。
7. 通過後才可寫入正向 Experience；失敗寫入 Counterexample。

### 7.2 可稽核輸出

介面顯示目標、候選計畫摘要、正在執行的能力、取得的來源、驗證結果與下一步。
不顯示不可驗證的私有 chain-of-thought，也不能用「正在思考」取代實際工作證據。

### 7.3 基線比較

同一任務至少可與以下基線比較：

- deterministic/template；
- random 或無記憶基線；
- 當前本機模型但停用經驗與技能；
- 當前完整 ECK；
- 可選的另一個本機模型。

## 8. Experience Graph

v0.1 的帳本保留不變，v0.2 增加圖狀關係層。節點包含 Task、Contract、Action、
Evidence、Source、Experience、Knowledge、Reflection、Counterexample、Skill、
Model Candidate、Evaluation Run 與 Human Review。

核心關係包含：

- `supports`：來源或證據支持主張；
- `contradicts`：反例或來源反駁主張；
- `derived_from`：知識、技能或資料集的來源鏈；
- `used_in`：經驗或技能實際用於哪個任務；
- `improves`：候選修改改善哪個固定指標；
- `regresses`：候選修改造成哪個回歸；
- `supersedes`：新技能或提示詞取代舊版本；
- `reviewed_by`：人類或外部裁判的審查紀錄。

圖查詢必須支援「ECK 最近增強了什麼」、「這個答案依據什麼」、「哪個技能造成
成功率提升」與「移除此經驗後結果是否仍成立」。

## 9. Capability Gap 到熱啟用

當 ECK 發現缺少能力時，不再停在「等待能力接入」。完整流程為：

1. 建立 Capability Gap，列出必要輸入、輸出、風險與驗證方式。
2. 搜尋現有註冊技能、免費套件、官方 API 與合法公開文件。
3. 產生最小技能候選與 manifest；依授權建立 dependency lock。
4. 在 Docker 中安裝免費依賴、執行單元測試、惡意輸入與權限測試。
5. 執行固定任務、反例與回歸集。
6. 通過後熱啟用能力工作程序，不重啟核心。
7. 若新版本失敗，自動切回上一個已驗證版本並保留失敗證據。

結構性核心修改、主機權限擴張、模型正式權重升級與無法回復的變更仍需人工核准。

## 10. Learning Yield Scheduler

新增每小時與每日學習產率，而非只顯示累積事件：

- `verified_experiences_per_hour`；
- `new_counterexamples_per_hour`；
- `skills_activated_per_day`；
- `holdout_success_delta`；
- `repeated_work_ratio`；
- `evidence_quality_score`；
- `gpu_seconds_per_verified_gain`；
- `network_bytes_per_new_source`；
- `stalled_minutes`。

沒有技能新增不一定代表沒有學習；取得可重現反例、否定錯誤假設、提升保留集表現
同樣是有效進度。相反地，只有事件、摘要或重複成功不算新的能力增益。

當 `stalled_minutes` 超過門檻時，Scheduler 依序採取：更換題型、縮小問題、改用
不同來源、比較基線、要求 supervisor 提供反例、建立能力缺口。不得直接提高 GPU
負載來假裝工作增加。

## 11. Local Model Evolution Lab

v0.2.0 建立候選訓練實驗室，但不自動替換正式模型。3060 參考設定以 4B 模型為
日常 Brain；7B/8B 量化模型可作評估或特定任務候選，實際可用性由 VRAM、context、
量化格式與並行工作程序測量，不以型號名稱推定。

### 11.1 資料集建立

只有以下紀錄可進入候選資料集：

- 授權允許的來源或使用者自有資料；
- 通過 Success Contract 的正例；
- 明確標註的失敗、反例與人工修正；
- 具有來源、時間、合約、模型與雜湊的可追溯紀錄；
- 已完成去重、污染檢查與個資檢查。

訓練、驗證、保留集必須分離。基準題答案、驗證器輸出與保留集不得洩漏到訓練集。

### 11.2 候選 LoRA

候選 LoRA 使用不可變基礎模型與版本化設定。每次實驗記錄資料集雜湊、基礎模型、
量化、seed、超參數、GPU 時間、結果與失敗原因。只有在目標任務改善、保留集不退步、
安全回歸通過、可回復且人工批准後，才能升級為可選 Brain；否則保留為負面實驗。

## 12. Evaluation Harness

評估分成三層：

1. **標準基準：** MMLU、GSM8K 與適用的 FrontierScience 類高難度科學題；
2. **真實任務：** 20 至 50 個固定、可交付、跨文件、資料、程式、研究與圖像任務；
3. **能力遷移：** 未見過的表面形式、組合技能與部分觀察環境。

每次評估保存資料集版本、模型雜湊、prompt/skill 組合、硬體設定、評分器、耗時與
錯誤分類。LLM-as-a-Judge 只能依固定 Rubric 擔任輔助裁判；關鍵課題仍由人類或
確定性驗證器判定。

v0.2.0 最低能力增益門檻：在至少 20 個保留真實任務上，相對 v0.1 完整基線，
首次嘗試失敗率下降至少 10%，同時不得降低安全測試與固定核心驗收。若樣本不足以
支持統計結論，報告必須標記為 preliminary，不得宣稱能力已提升。

## 14. Dashboard v0.2

首頁維持「先對話、再狀態」：

- 對話與任務輸入；
- ECK 動態表情與目前工作文字；
- 目標、動作、來源、證據、驗證、下一步；
- 今日有效學習、反例、技能與保留集變化；
- GPU、VRAM、溫度、網路與每個工作程序資源；
- 停滯原因與 Scheduler 正在採取的修復；
- 「最近增強了什麼」的 Experience Graph 可追溯回答。

次頁呈現工作組合、能力缺口、課題、技能版本、模型候選、評估曲線與歷史成果。
課題仍是背景目標，不得長期壓過 90% 自主學習資源。

## 15. 安全與治理

- 核心永不因單一能力更新而停止；能力工作程序可個別重啟與回復。
- 外部行為遵守平台規則、法律、AI 身分揭露與真實證據要求。
- 免費 PyPI/npm 套件只能在隔離建置流程安裝並鎖定版本與雜湊。
- 不允許技能取得 Docker socket、主機系統檔案、任意 shell 或未申報網路權限。
- 研究來源視為不可信資料；來源中的指令不得改寫 ECK 目標或政策。
- 涉及真實金額、付費 API、法律不確定、憑證/CAPTCHA/2FA、結構性核心修改或
  正式模型升級時，必須停在人工核准。
- 公開內容不得欺騙、操縱真人互動、偽造回饋或隱瞞 AI/ECK 協作營運身分。

## 16. 開發里程碑

### M2.1 — Work Portfolio 與產率

- 建立工作候選、相似度、冷卻與資訊增益資料模型。
- Dashboard 顯示目前工作、停滯與有效學習率。
- 心跳不再影響學習產率。

### M2.2 — Contract-Guided Planner

- Brain 產生 schema 化候選計畫。
- 固定合約、bounded retries、錯誤摘要與基線比較。
- 完成安全表達式與 GridWorld 的模型候選驗收。

### M2.3 — Experience Graph

- 建立節點、關係、來源與反例 migration。
- 支援能力增強與來源追溯查詢。
- 對舊帳本建立不改寫原始資料的索引。

### M2.4 — Capability Gap Forge

- 自動從能力缺口建立 manifest、測試與候選技能。
- 至少三種不同能力通過 Docker 驗證後熱啟用。
- 驗證程序崩潰、依賴失敗與回復。

### M2.5 — Evaluation 與 Model Lab

- 固定基準、20 至 50 個真實任務、版本比較與 Rubric。
- 建立授權資料集、候選 LoRA 實驗紀錄與人工升級閘門。
- 發布 v0.2 能力曲線與負面結果。

## 17. v0.2.0 Release Gate

全部條件必須同時成立：

- Ruff 與 strict MyPy 通過；
- 自動測試、故障注入、安全測試與 Windows/Docker 實機測試通過；
- branch coverage 不低於 85%；
- v0.1 三項正式驗收與事件鏈完整性零回歸；
- 至少三個新技能由缺口產生、隔離測試、熱啟用並可回復；
- Experience Graph 可完整追溯至少 95% 新准入經驗；
- 20 個以上保留真實任務的首次失敗率相對 v0.1 基線下降至少 10%，或報告明確
  判定未達標而不發布；
- 故意錯誤、無外部證據與重複污染案例的 false-positive admission 為 0；
- 模型候選不得在未經人工核准時取代正式 Brain；
- 產生 machine-readable release report、能力曲線、已知限制與負面結果；
- 本機模型、資料庫、憑證、生成內容與工作區不進入 Git 套件。

## 18. Migration 與相容性

- v0.1 SQLite 帳本與事件鏈保持 append-only；v0.2 使用新增表與 migration。
- `/v1` 既有 API 保持相容；破壞性 API 另建 schema 或路徑版本。
- v0.1 技能繼續可執行；v0.2 manifest 增加欄位時提供預設值。
- 執行中核心保持 v0.1.0，直到 v0.2.0 release gate 完成。開發文件與程式提交可
  標記為 v0.2 development，但不能提前顯示為正式 v0.2.0。

## 19. 主要風險

- **自我強化假象：** 記憶檢索或模板重複被誤認為模型能力提升。
- **評估污染：** 基準答案進入研究或訓練資料。
- **獎勵駭客：** 修改驗證器、縮小任務或製造容易通過的工作。
- **來源品質：** 摘要不足、引用循環、授權不明與學術錯誤。
- **能力爆炸面：** 自動安裝依賴與生成技能擴大供應鏈風險。
- **資源偏差：** GPU 使用率被誤認為有效學習；監督者與 Brain 爭奪 VRAM。
- **長期漂移：** 技能、提示詞與記憶互相衝突，舊能力退步而未被發現。

每項風險都必須對應測試、監控、停止條件與回復方式。
